Quick start ​

Every feature of Jevwright can be tried in a few minutes on the Demo App, a small online shop we host for you. This page shows how, and then what your own app needs.

The Demo App ​

The Demo App is a copy of the Swag Labs shop at https://demo.94.72.126.118.sslip.io. You sign in, add products to the cart and check out. Its sign-in page lists the test users; all of them use the password secret_sauce:

UserHow the shop treats them
standard_userEverything works
locked_out_userCannot sign in; the shop shows an error
problem_user, performance_glitch_user, error_user, visual_userBroken images, slow pages, errors or a shifted layout, to see how tests react

The shop keeps the signed-in user in a cookie named session-username, so a test can start already signed in by setting that cookie (see buy-a-backpack.yaml below).

1. Register ​

Open the web workspace and register with an email and a password. Your account starts with a Quick Start project in the sidebar. Its Variables are already set:

VariableValue
BASEhttps://demo.94.72.126.118.sslip.io, the Demo App
SWAG_PASSWORDsecret_sauce

Every Quick Start file starts with baseUrl: "{{BASE}}", so it tests the Demo App. If you delete the project, Add the Quick Start project under the sidebar's tree brings it back.

3. Run a passing test ​

Open sign-in-and-see-products.yaml and click Run (or press Ctrl+Enter). The Output console on the right follows the Run live, step by step. A passing Run ends like this:

text
Passed  6/6 passed
Step 1  open     line 8   Passed
Step 2  input    line 10  Passed
Step 3  input    line 13  Passed
Step 4  click    line 16  Passed
Step 5  waitFor  line 18  Passed
Step 6  assert   line 20  Passed

Click Open run details to see the report: every step with its duration, how its element was found (selector here), and a screenshot of the page after it.

4. Run a failing test ​

Open wrong-total-fails-at-the-total.yaml and run it. It expects a total of $99.99, but the shop charges $32.39, so step 10 fails, and steps 11 and 12 stay Pending, because a Run stops at the first failed step. The failed step shows its reason and a screenshot of the page at that moment:

text
Text of "[data-test="total-label"]" did not contain "Total: $99.99" within 3000ms; it was "Total: $32.39"

Do what the file's # Try: line says, fix the total, and run it again.

5. Let Jev find and judge ​

Open the files in 4 Jev - find and check by description:

  • find-elements-by-description.yaml has no selectors for its buttons, only a target such as "'Add to cart' button of the Sauce Labs Backpack". The report shows visual or dom for those steps: Jev found them.
  • fall-back-from-a-stale-selector.yaml has a selector that no longer matches. The step also has a target, so Jev finds the button and the step passes; the report shows how.
  • judge-a-true-statement.yaml and judge-a-false-statement.yaml check the page with a statement in plain words, which Jev judges from a screenshot. The false one fails with a reason that starts with Statement does not hold.

6. Fix an invalid file ​

Open seven-errors-at-once.yaml. The Debug console lists every problem with its line and its code, such as Line 9: Unknown action "aiAct" with E005, and the editor underlines each line. Click a problem to jump to its line. A file with problems cannot run. Fix them one by one; the list updates as you type and when you save. The Diagnostics page explains every code.

Test your own app ​

When you are ready to test your own app, check two things first.

Your app must be public

Runs happen on our server, which reaches public web addresses only. localhost, private IP addresses such as 192.168.1.20 or 10.0.0.5, an intranet, or a host you reach only over a VPN fail, usually with net::ERR_FAILED or net::ERR_CONNECTION_REFUSED on the open step. Deploy the app, or a preview of it, to a public domain such as https://staging.example.com.

A sign-in needs a session the test can set

A test cannot solve a CAPTCHA, a code sent by email or text (2FA), or bot protection. Either sign in with a test user whose sign-in has none of these, or start the test already signed in: put a session cookie, a token header, or a storage entry in the file with cookies, headers, localStorage or sessionStorage, and keep the token itself in a Project Variable.

Then create a Project for your app, set its BASE Variable to your app's URL, and follow the General workflow.
